# 定式教学：主动识别 + 棋盘浮层参考图

日期：2026-10-17 ｜ 目标版本：v3.6.0 ｜ 状态：**已定稿（用户确认「这个功能已经可以了」）**

---

## 一、意图与为什么

这个项目里最有效的学习时刻，是**她讲定式的那一下**——用户原话：那种「原来该这么下」的感觉就是在那一刻冒出来的。

但现在这套定式教学是**被动**的：

| 现象 | 现状（v3.5.2 代码） |
| --- | --- |
| 什么时候认出来 | `JosekiRecognizer.scan()` 每次只看**最新一手所在的角**，且只在两种时刻给结果 |
| 什么时候讲 | ① 序列**恰好走完**（`formed`）才讲一句；② 你**偏离**一个已吻合 ≥4 手的定式，才点一下「该下哪」。**中间几手一声不吭** |
| 讲多少 | 一句话（库里写死的 `key`）+ 棋盘高亮轨迹 |
| 记不记得 | `joseki_log` 是**局内**的，`reset` / 重开一局就清空 |
| 认识多少 | 库里 7 条，**起手全是星位**（点三三 / 小飞挂 / 双飞燕）。小目、三三、目外一条都不认识 |

用户要的是把它翻过来：**主动识别、提前介入**，并且在关键位置用**比一条文字点评更重的呈现**。

---

## 二、目标

1. **主动识别 + 提前介入**：角上一进定式场景（出现库里某条的起手）就认出来并开口，之后跟着走，不再等走完。
2. **只在结构点开口**：进入 / 分岔 / 收尾三处说话；中间吻合的推进**一句不说**，走回普通的每手点评。
3. **重呈现**：定式期间，棋盘上浮一张**参考图卡片**——一张小棋盘画出这条定式的完整次序，标出你俩现在走到第几手，跟真实对局同步。
4. **次数记忆**：同一条定式**前 3 次出现**都上卡片；**第 4 次起**只在你**真的亏了**的时候才上卡片。这份次数**后端持久化**，跨局、跨重启不丢。
5. **扩库一门功课**：把小目、三三、目外的常见开局形状补进来，并给核心定式补出**分岔**（同一前缀下的替代线）。

---

## 三、非目标

- **不考你**：不做「这手你会怎么下？」的提问式教学（用户在「提前介入 / 主动考你」之间选了前者）。
- **不手动标重点**：不做让用户在配置里挑「重点定式」的入口——**她自己按出现次数挑**。
- **不做回放器**：卡片是**常驻参考图**，不是可以「上一手 / 下一手」点着走的动画（四稿里选了 B 的形态，没选 C）。
- **不做双棋盘对照**：不在卡片里并排画「正解 / 你走的」两个小棋盘（四稿里没选那一稿）。要指出你走错的那一手，就在**同一张小棋盘上把它标出来**。
- **不给大棋盘加手顺编号 / 连线**：保留现有那条简单的高亮轨迹，不加棋书式的编号连线（四稿里没选那一稿）。
- **不动语音链路**：一切照旧走现在的后端清洗 + 合成 + `speech` 事件。卡片是**纯视觉**的，不进台词、不产生语音。

---

## 四、反目标（用户点名的两条，当硬约束）

用户明确说，下面这两种情况**即使功能跑通了也算白做**：

1. **她变话多**——定式期间一直在讲，把「安静下一盘」的节奏打碎。
2. **卡片挡事**——右栏本来就是一堆控件，卡片一挤，界面反而更难用。

由反目标推出的两条设计原则（贯穿全文）：

- **话是有代价的，卡是安静的**。一条定式全程只开口 1~3 次；讲不完、需要反复看的东西一律**放进卡里**，不靠嘴说。
- **卡片不得挤压已有控件**。这是它最终没进右栏、而是浮在棋盘上的原因。

## 六、我替用户定的（都可以推翻，标出来只为让你一眼看到）

| # | 决定 | 理由 |
| --- | --- | --- |
| A | **进入**的判定：最新一手落在某个角内，且该角出现了库里某条的起手（星位已存在 + 有人点三三 / 挂角） | 复用现有 `scan()` 的角判定与前缀游走 |
| B | **收尾**的判定：库里那条线**走完**，或**任一方脱先**（下一手落在角外）。两种情况都收尾：说总结、卡片收起 | 「角上告一段落」的两种自然形态 |
| C | **分岔**的判定：吻合到第 k 手时，库里存在 **≥2 条**以这 k 手为前缀、且第 k+1 手不同的线条 | |
| D | **走错**加一条护栏：如果这手**正好是库里的那一手**，不判走错 | 否则库里线条本身略亏时会出现「照书下还被骂」 |
| E | 「第几次出现」按**这条定式出现**计数，不按走完计数（**v3.7 起口径修订**：加入频率层后，族计数改记**讲解次数**——未命中不消耗「前 3 次」预算，否则频率层会把教学预算静默吃掉；见 `tests/test_joseki_gate.py`） | 目标是多见几遍，不是考能不能走完 |
| F | 讲解**并进那一手的发言位**，不额外多一条台词：你这手走完的并进点评，她走完的并进落子宣告 | 守住「同一时刻不出现两条气泡」；代价是她走完的那种情况棋子揭示多等半句 |
| G | 进入那一手**不再单独点评**，那句「这一角是点三三」顶替它的排名评价 | 同上 |
| H | 卡片的缺省避让：浮在棋盘**空白角落**、半透明、可拖动；鼠标靠近或与落点重叠时淡出；定式收尾后收起 | 这是「浮在棋盘上」唯一真实的缺点（可能压住你要落子的地方） |
| I | **计数的单位是「族」，不是「定式名」也不是「单条线条」**。族＝一课的粒度（如 `star_33`＝星位点三三、`komoku_low_kakari`＝小目一间低挂），由写库时**显式给每条定式标一个族 id**，不从名字里切。同族的多条线条（基本型 / 定形 / 两种次序）**共用**那份「前 3 次」额度 | 现有库里有「同名但手顺不同」的条目（点三三·定形有两条、双飞燕·靠压一边有两条含延伸），按名切或按条切都会撞问题：按名切在扩库后会把「小目·一间低挂」的飞 / 靠 / 夹三条不同课并成一个额度；按条切又会让同一条课的两个次序各烧一份额度。族是这两者之间的正确粒度 |
| J | **分岔时卡片只画一张小棋盘**：画你俩实际在走的那条线（已吻合前缀 + 与你这手一致的那条线的剩余部分）；只要还没选定其中一条，卡片就在**下一步的位置把各候选点标出来**（不同记号），由讲解说清差在哪。一旦你这手选定，卡片回到单线 | 用户明确不要「双棋盘对照」；一张卡片上标出候选，是「说清分岔」和「不炸界面」之间唯一同时成立的画法 |
| K | **入围次数的记账规则**：每个族**在同一局里最多计 1 次**（同族的多个角、多条线都算同一次）；**悔棋回档时，把这一局已计的那一次从持久记录里退回去**（-1） | ① 同局最多 1 次，避免一局里摆两次同一个定式就把 3 次额度烧光、下一局直接不给卡片；② 现有设计里悔棋重走那一手**本来就可以重新讲解**（`joseki_log` 随快照回滚），计数若不同步回退，用户会看到「我就回档重走一遍，怎么就不讲了」——这是明显的困惑点 |

### 6.1 用户追加（2026-10-17）：定式提示频率可调

- 定式提示**不再每手都触发**：新增 `joseki_rate`（0~1，默认 0.5），实际概率 `p = clamp(rate + skill_adj + mood_adj, 0, 1)`——**棋力画像与情绪各带来 ±10% 的浮动**。
- **未命中 → 只点评这一手**（不讲定式、不上卡片），且与「没识别到定式」**逐字段同构**。
- **走错永远优先**（绕过概率必讲）；同一族在最近 N 手（建议 N=8）内**冷却**。
- 门控**只决定文本与卡片**：不改棋子、不改 `speech` 配对、不改 `busy`。机制细节见计划《核心机制：定式提示门控》。

## 八、接口草图（够你规划，不构成实现约束）

### 8.1 识别器需要多给两样东西

现在 `JosekiRecognizer.scan(moves)` 返回 `formed` / `deviated` 两种结果，且**只给吻合前缀的实际棋盘点**（`points`）。卡片要画**完整次序**，所以还需要：

1. **库里那条线的全部着子，落到真实棋盘坐标上**（含颜色），并按当前角的朝向 / 换色正确映射——现有 `tr`（对角镜像）与 `same`（换色）两个标志就够算出来；
2. **当前进度 k**（你俩走到这条线的第几手），以及**候选线条集合**（用于分岔：同一前缀下还有哪几条、下一步各是什么）。

### 8.2 识别结果的种类

`entered`（进入） / `branch`（分岔） / `formed`（收尾·走完） / `swept`（收尾·脱先） / `mistake`（走错：偏离 + 真亏）。

> 现有 `deviated` 的语义要改：从「偏离库线」改成「**偏离库线且真的亏了**」，并叠上第 6 节的护栏 D（库里那一手不判错）。

### 8.3 事件

沿用现有 `joseki` 事件的通道（前端 `Board3D` 已在消费它的高亮轨迹），扩出卡片需要的字段：定式名、角的方位、完整手顺（真实坐标 + 颜色）、当前进度、结果种类、以及走错时**该被标出来的那一手**。

**语音与事件序列的硬要求**：这套东西**不得**改变任何一条台词与 `speech` 事件的配对关系；卡片不产生语音、不进台词。

### 8.4 次数记录

后端本地一份持久化记录（性质同 `memory.db`：运行产物、不入库、已 gitignore）。**不设开关**——它是这个功能的核心，不是可选特性。

必须守的纪律（沿用长期记忆那套，因为它踩过同样的坑）：

- 同步的文件 / 数据库调用**不得直接放进 `async def`**；用 `asyncio.to_thread(...)`，否则单 uvicorn 事件循环会被卡住；
- **任何存储故障都只打日志、绝不影响对局**：记录读不出来就当成「第 1 次」，写不进去就只丢这一次的记忆；`busy` 照常归位；
- 记录的 key 是第 6 节 I 定义的**族 id**（不是「角 + 名」）——同一条定式换个角出现，教学记忆应当延续；
- 记账按第 6 节 K：**同族同一局最多计 1 次**；**悔棋回档时把本局已计的那一次退回去**（-1）。退不回去也只记日志，不影响对局。

### 8.5 前端

- 一个浮层卡片（新的 UI 脚本）：小棋盘 + 手顺 + 进度 + 一句讲解 + 标出你走错的那一手；避让 / 拖动 / 淡出按第 6 节 H。
- `Main.gd` 只做接线（沿用现有风格：节点与 UI 都在代码里构建）。
- 卡片是 **2D Control 浮在 3D 场景之上**——与现有左右栏面板同一套做法，不涉及 3D 改造。**修正一处我先前的说法**：第二轮我说「3D 场景里飘 2D 板子，风格要重新设计」，那是我说过头了，实际与现有面板一致。

### 8.6 提示词

进入 / 分岔 / 收尾各自需要一句讲解（LLM 组织，库里 `key` 是素材）。注意 `tests/golden/prompts.json` 锁定了「`long_term` 为空时 `context_block` 输出逐字符不变」——新增模板函数没问题，**改 `context_block` 绝对不行**。

### 8.7 门卫

- 后端（标准库 `unittest`，不得引入 pytest）：识别器新种类（含分岔 / 收尾两种形态 / 护栏 D）的黄金样本；次数规则（前 3 次 / 第 4 次起的分支）；持久化跨实例；存储故障降级（读不出、写不进，`busy` 必须归位）。
- 前端（Godot headless）：卡片状态机——事件 → 进度 / 标错 / 收起，纯逻辑无外部依赖。
- 现有门卫必须继续全绿：后端全量 + `katago_service` 全量 + 前端 `test_config.gd` / `test_tts.gd` / `test_speech_pairing.gd`。
