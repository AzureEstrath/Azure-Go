# 策略线与情绪波动 + 事件表

日期：2026-10-17 ｜ 目标版本：v3.8.0 ｜ 状态：**草案（待用户过目）**

> 这是**第三个**独立项目，排在「定式教学（v3.6.0）」与「体验与可靠性批（v3.7.0）」之后。
> 它不依赖前两者，但**复用**它们的既有物：`mood` 三维情绪、`prompts.context_block`、`GameState`、`AI_DEDUP_WINDOW`。
> 实施计划见 `plans/2026-10-17-joseki-and-ux-master.md` 的「阶段三」。

---

## 一、意图与为什么

| 现象 | 现状 |
| --- | --- |
| 她没有「计划」 | `_pick_ai_move` 只取引擎候选里**第一个合法点**，走一步算一步，没有「我想连着走成什么」 |
| 她不会「下偏」 | 永远走引擎给的最优候选，不像人；情绪只影响表情与台词，**不影响落子** |
| 她记不住盘上发生过什么 | 台词只带最近 8 条窗口与滚动 18 条的 `memory_log`；「这盘棋我先亏了一手、你后来又送我一块」这种**跨手脉络**没有载体 |
| 提示词没有「事件」概念 | `prompts.context_block` 只有棋谱 / 记忆 / 聊天三段，**没有任何「发生过的事」的结构化输入** |

想要的是三件事：**她心里有一条五步计划**、**她可能小概率走偏**、**这盘棋的事被记成一张带时刻的表并按档位喂回给她**。

---

## 二、目标

1. **预测线 A**：从当手棋起，引擎给出的**下五步最优解**（连续手顺）。
2. **预测线 B**：从当手棋起，**另一条不同的最优解**，与 A **至少 2~3 步不同**（可调）。
3. **预测线 C**（2026-10-17 追加）：从当手棋起，**第三条**最优解，与 A、**且与 B 都**至少 2~3 步不同；**三条线全部取自同一次分析**。
4. **情绪波动开关**（默认关）：开启时，她**小概率**在 **A / B / C 阶梯**里选一条（越偏越少）落子，让落子带上「人味」；关闭时行为与现状**完全一致**。
5. **事件表 + 遗忘权重**：对局中发生的事件**带时刻**写入一张**只增不减**的表；每条事件按**随步数淡化的档位**（4 档）改写后注入提示词。
6. **提示词架构增量翻新**：新增**「事件区块」**，插在**铁律段之前**；把整条提示词组装显式写成**区块表**（来源 / 插入点 / 上限 / 失效条件）。

---

## 三、非目标 / 反目标（点名的两条当硬约束）

- **不许拖慢对局**：线 A/B 与事件区块**不得引入任何额外的 KataGo 分析**；聊天摘要**默认不引入额外 LLM 调用**（见第四节）。
- **不许把棋盘弄坏**：走 B 必须是**引擎候选中的合法点**、且与 A 的胜率差有上限；宁可降级回 A，也不许下出烂棋。
- **不许她变话多**：事件表是**给模型看的素材**，不是台词；事件原文**永不进台词**、**不产生 `speech`**。
- **不改既有硬规则**：音画同步（`ai_move` 带坐标、语音开始才 `reveal`）、`busy` 必归位、`context_block` 的 golden 锁定，**一行不动**。

## 四、性能红线（第一位，先读这条）

| 红线 | 做法 |
| --- | --- |
| **零额外引擎调用** | 线 A/B **只从既有那次 `after_infos` 里抠**（KataGo `moveInfos` 每条自带 `pv` 与胜率）；**不再新开分析** |
| **零额外 LLM 调用（默认）** | 聊天摘要**默认走规则式**（关键词 / 相似度分段 + 模板摘要）；仅当 `chat_digest_llm=true` 才用 LLM，且**只在局末 `summarize()` 或空闲时**补做——**落子回合内不加调用** |
| **`MAX_LLM_CALLS_PER_TURN = 4` 不放宽** | 任何新增 LLM 调用都必须落在既有预算内或回合之外 |
| **提示词有界** | 事件表**存储层完整**（从开局到当前，只增不减）；**注入层**受「衰减窗口 + 字符预算」双重限制，超限时丢最旧 / 最低档 |
| **纯计算，无阻塞** | 线 A/B/C、档位计算、区块渲染都是**纯函数**（O(候选数)）；磁盘 / DB 若引入一律 `await asyncio.to_thread(...)` |
| **唯一被允许的代价** | 三线要求**更深的搜索**（实测 `maxVisits` 100→200），使**那一次已有的分析变慢**、但**不增加调用次数**。若用户不接受这个代价，就降级为「A/B 两线」或「pv 不足时用可用长度」 |

**已定（用户原话要点）**

| # | 决定 |
| --- | --- |

| 2 | 情绪波动做成**开关**；开启时**小概率**下偏优解——在 **A / B / C 阶梯**里选（越偏越少：A 常态 → B 小概率 → C 更小概率） |
| 3 | 事件表要**带时刻**；**包含从游戏开始的每个事件** |
| 4 | 聊天事件：**LLM 发出消息后**按**主题裁切最近聊天、分段总结**写入；**不要反复写入同一内容** |

| 6 | 提示词架构**增量翻新**；事件做成**区块**；改完要**人能读懂、也能直接交接给 code AI** |

**我替用户拍的（可推翻，标出来只为让你一眼看到）**

| # | 决定 | 理由 |
| --- | --- | --- |
| A | 「下五步」= 首手 + `pv` 前 4 手；`pv` 不足 5 手时**降级**（A 只留首手，B 判为缺失），不报错 | 引擎 `pv` 长度不保证；降级不崩是项目纪律 |
| B | 线 B / C 选取：在**前 `pv_candidates`（默认 10）** 个候选里**依次**取「与**已选的每一条线**都满足**不同手数 ≥ `pv_diverge_min`（默认 2）**、且**胜率差 ≤ `pv_max_drop`（默认 5%）**」的候选，凑够 **B、C**；凑不齐就**有多少用多少**（只有 A/B，或只剩 A） | 保证各线「真的不同」且「不至于太差」；三线不足时降级、不报错 |
| C | 情绪波动概率 `p_drift = clamp(drift_base + emotion_bias(mood), 0, drift_max)`；`drift_base=0.03`、`drift_max=0.08` | 小概率、有上限，避免变成「乱下」 |
| D | B 缺失 / 胜率差超限 / `emotion_drift=false` → **一律走 A**（与现状同构） | 安全缺省 |
| E | 事件表用**局内内存**（`reset` 清空），**不新建持久化**；长期记忆（`memory.db`）是另一个功能，不复用 | 减复杂度、少运行产物 |
| F | 事件表**不随悔棋回退**（悔棋本身也是一次事件） | 「发生过就是发生过」；也符合「包含每个事件」 |
| G | 淡化档位：`DECAY_SPAN = [1, 3, 6]`（第 1 档持续 1 手 → 第 2 档到第 3 手 → 第 3 档到第 6 手 → 第 4 档），`DECAY_DROP_AT = 12`（超过 12 手仍留在表里，但**不再进提示词**） | 权重＝持续步数、程度＝固定档，正是用户的分工 |
| H | 事件区块**为空串时输出逐字符不变**，插入点必须在**铁律段之前** | 守住 `tests/golden/prompts.json` |
| I | 事件区块有**字符预算** `EVENT_BLOCK_MAX_CHARS`（默认 240，与 `memory_max_inject_chars` 同量级）；超限按「最旧 → 最低档」丢弃 | 防止对局变长后撑爆提示词 |
| J | 聊天摘要**默认规则式**；`chat_digest_llm=true` 才用 LLM 且在**局末 / 空闲**补做 | 守住第四节性能红线 |
| K | 开关与参数放**设置抽屉**（v3.7 · D1 那一格），**不新增右栏控件位** | 守住「界面更挤」反目标 |
| L | **线 C 的用途**：情绪波动按「**越偏越少**」的阶梯在 A/B/C 里选（B 的概率 > C 的概率）；**C→B→A 逐级回落**（首手非法就退一条）；C 同时是提示词素材（她可以提「我还有另一条路子」） | 让第三条线有明确用途，不做摆设 |

## 六、接口草图（够你规划，不构成实现约束）

### 6.1 预测线（纯函数，零引擎调用）

```python
# backend/app/pv_lines.py
def extract_lines(move_infos, *, pv_len=5, diverge_min=2,
                  max_drop=0.05, candidates=10) -> dict:
    """
    只吃既有的一次 after 分析结果（moveInfos）， 不再调引擎。
    返回：
      {
        "a": {"moves": ["Q16", "D4", ...],  # 长度 ≤ pv_len，首手在最前
              "winrate": float, "score": float},
        "b": {"moves": [...], "winrate": float, "score": float,
              "diff_from_a": int} | None,
        "drop": float,          # A 与 B 的胜率差（b 为 None 时 0.0）
      }
    """
```

- 输入来源：`agent._ai_turn` 里**已有的** `after_infos`。
- ✅ **实测结论（2026-10-17，本机 `bin/katago` + `model-b18c384nbt`，配置 `analysis_example.cfg`）**：
  - `moveInfos[]` **确实带 `pv`**（字段：`move / pv / winrate / scoreLead / visits / order / prior / lcb / utility / …`）——**无需任何额外引擎调用**即可取线。
  - **`pv` 长度由「该候选被访问的次数」决定**，`analysisPVLen` 只是**上限**。
  - 同一次分析（开局 `Q16 / D16` 后）实测：**30 visits → pv 只有 1~7 手（不够五步）**；**200 visits → pv 6~10 手（够五步）**，且前 5 个候选两两差异 ≥2 手，**A/B/C 三条线都凑得出来**。
  - ⚠️ **两个部署前提**：① 引擎配置必须**显式设 `analysisPVLen`**（本项目 `default_gtp.cfg` 与 `analysis_example.cfg` 里它都是**注释掉的**）；② 要让 B/C 也有五步，需要**更高的 `maxVisits`**（本项目默认 100；实测 200 才稳）。
  - ⚠️ **性能代价（唯一被允许的代价）**：提高 `maxVisits` = **那一次已有分析变慢**（单线程实测 200 visits ≈ 9.8s）。三线**不增加调用次数**，但**要求更深的搜索**——必须写进 README / AGENTS。
- A = `move_infos[0]` 的 `move` + 其 `pv` 前 `pv_len-1` 手。
- B = 见第五节 B 条；逐手比较用 GTP 坐标。

### 6.2 情绪波动（开关 + 小概率）

```python
# 决策点：_ai_turn 选出 A 之后、真正落子之前
# 阶梯：A 常态 → B 小概率 → C 更小概率（越偏越少）；三条线都来自同一次分析
p = p_drift(mood)      # = clamp(drift_base + emotion_bias(mood), 0, drift_max)；rng 可注入，便于测
```

- 具体阶梯形状留给你定；**要点是 `P(走 A) > P(走 B) > P(走 C)`**。
- 选定后 → 落点用该线首手；**`C → B → A` 逐级回落**（所选首手不是当前棋盘合法点，就退到上一条线）。
- 走 B / C 时对提示词与事件标注「这是一次**自主偏航**」。

### 6.3 事件表（存储：只增不减）

```python
# backend/app/event_log.py
Event = {
  "move_no": int,        # 对局时刻（主）：用于衰减
  "ts": float,           # 墙钟（辅）：只为可读性 / 调试
  "kind": str,           # 见下
  "text": str,           # 给模型看的一句原始描述（永不进台词）
  "detail": dict,        # 结构化字段（影响 / 后果 / 方位 / 主题 …）
}
kind ∈ {
  "ai_bad",       # 我（Azure）下错了 / 走了偏优解
  "player_bad",   # 玩家下了步不好的棋
  "player_good",  # 玩家下了步好棋
  "chat",         # 玩家和我聊了（主题 + 摘要）
  "joseki",       # 定式成型 / 偏离（与 v3.6 联动，可选）
}
```

- `EventLog.add(kind, move_no, text, detail)`：**去重键 = `kind` + 归一化 `text`**，命中则**不写**（「不要反复写入同一内容」）。
- `EventLog.all()` 返回**从开局到当前的全部**事件；`reset()` 清空。
- **不进 `GameState` 快照**（不随悔棋回滚，见第五节 F）。

### 6.4 遗忘权重 / 淡化档位（纯函数）

```python
# backend/app/decay.py
DECAY_SPAN    = [1, 3, 6]     # 权重：每档持续多少手（只决定「多少步」，不决定程度）
DECAY_DROP_AT = 12            # 超过则不再进提示词（仍留在表里）

def level(move_no_of_event: int, now_move_no: int) -> int:   # 返回 1..4
```

**四档文案模板**（程度固定，与权重无关；`{方位}` 由坐标推，核不上就不说方位）：

| 档 | 文案 |
| --- | --- |
| 1 | 我在 **{n} 手**下错了，影响了 **{影响}** 导致 **{后果}**，我要进行微量的情绪平衡来调整 |
| 2 | 我在 **{n} 手**下错了，目前因为那一步 **{…}** |
| 3 | 我在 **{n} 手**下错了一手 |
| 4 | 我 **{左上 / 左下 / 右上 / 右下}** 下错过一手 |

> 档 1→4 = **信息量递减**（原因 / 后果 → 只留事实 → 只留方位）；权重只决定**每档停留的手数**。

### 6.5 提示词事件区块（增量翻新）

```python
# backend/app/prompts.py
def event_block(events: list[dict], now_move_no: int,
                max_chars: int = EVENT_BLOCK_MAX_CHARS) -> str:
    """``events`` 为空 / 全部超出衰减窗口 → 返回 ''（逐字符不变）。
    渲染顺序：新 → 旧；超预算时丢【最旧 → 最低档】。"""
```

**组装位置（区块表）**

| 区块 | 来源 | 插入点 | 上限 / 失效 |
| --- | --- | --- | --- |
| **事件区块**（新） | `EventLog` + `decay.level()` | **铁律段之前** | `EVENT_BLOCK_MAX_CHARS`；超 `DECAY_DROP_AT` 失效 |
| 铁律段（不动） | 既有 | 原位置 | 逐字符锁定 |
| 棋谱 / 记忆 / 聊天（不动） | 既有 | 原位置 | 既有上限 |

> 新内容**只能插在铁律段之前**；`long_term` 为空时 `context_block` 仍须**逐字符不变**。

### 6.6 聊天事件写入（性能敏感）

- **触发**：`agent.chat()` 里**她回复完之后**。
- **处理**：对「这轮玩家消息 + 她的回复」做**主题裁切**（把最近聊天按主题分段）→ 写成一条 `chat` 事件（主题 + 一句摘要）。
- **默认零 LLM**：主题分段用**规则式**（时间窗 + 关键词 / 相似度）；摘要用**模板**。
- **可选 `chat_digest_llm=true`**：用 LLM 分段总结，但**只在局末 `summarize()` 或 `idle` 时**补做，保证落子回合内零额外调用。
- **去重**：主题 + 归一化摘要命中已存在 → 不写。

## 七、门卫

- **后端**（标准库 `unittest`，不得引入 pytest）：
  - `pv_lines`：A 正常提取；`pv` 不足 5 手降级；**B、C 依次**满足「与已选各线不同手数 ≥ `diverge_min`」与「胜率差 ≤ `max_drop`」；**C 凑不齐 → 只有 A/B**（不报错）。
  - 情绪波动：`emotion_drift=false` → 恒走 A；`p_drift` 截断；注入 rng 可复现；B 非法点 → 回落 A。
  - `event_log`：去重不写重复；`all()` 覆盖从开局到当前；`reset` 清空。
  - `decay`：`level()` 在 `[1,3,6]` 边界与 `DECAY_DROP_AT` 处的取值。
