## 一、意图

定式那条线解决的是「她怎么教你」。这一批解决的是**其余那些每天都会碰到、但一直没被收拾的东西**——不是新功能，是把现有的东西做顺。

用户在候选池里挑了 6 项（**E1 / D1 / B2 / B3 / C3 / C2**），其余（C1 提示分三级、A 组上手门槛、B1 音效、D2 两栏合并、E2 自检面板、E3 一键门卫）**明确不做**，留在候选池里。

---

## 二、范围：6 项，按「改哪一侧」分组

| # | 是什么 | 触及 |
| --- | --- | --- |
| **E1** | `busy` 看门狗：后端给每个公开回合方法加一层兜底超时 | 后端 |
| **C2** | 局后**只读回看**：结束一局后能一手一手翻棋谱、看当时双方在想什么 | 后端 + 客户端 |
| **D1** | 右栏收纳：一次性设置收进「⚙ 设置」抽屉 | 客户端 |
| **B3** | 视角便捷：一键回初始视角 / 看向某个角 | 客户端 |
| **C3** | 把「目差 ±x.x」翻译成人话 | 客户端为主 |
| **B2** | 最后一手标记 + 悬停显示坐标 | 客户端 |

**成本修正**（独立评审之后）：**E1 由「低」升为「中」**（要带代际守卫，会碰编排的写入点），**C2 也比原估的大**（需要一个后端复盘模式 + 一份新的逐手存档）。其余四项仍是小项。

## 三、逐项设计

### E1 · `busy` 看门狗

**为什么**：`busy` 不归位是本项目**最严重的故障形态**（棋盘永久锁死）。现在只靠两层：后端 `try/finally` + 前端每帧清锁。一旦出现一条谁都没料到的异常路径，玩家看到的就是「棋盘点不动」。

**怎么做**：在每个公开回合方法的**外面**包一层兜底超时——不改动任何现有的 `busy` 位置（`agent_graph.py` 里那 5 条硬规则与「位置按阶段编码」不动），只在最外层加保险。

**先说一个必须解决的陷阱**：公开回合方法的开头是 `if self.busy: return`——这既是 UI 锁，也是**互斥锁**。所以「超时就把 `busy` 清掉」会**放开并发**：玩家立刻能再落子，而在途的那趟编排还在写 `st.moves` / `snapshots` / `bad_moves` / `_reveal_pending`。两趟编排并发写同一份状态，比「棋盘锁死」更糟。因此 E1 **不能只解锁**，必须同时做到：

1. **代际守卫**：给 agent 一个自增的代数；每趟编排开始时记住自己的代数，**每个写入点前**核对是否还是自己那一代，不是就整趟放弃（不写状态、不发事件）。超时触发时把代数前推一格，在途那趟从此变成哑巴。
2. **超时基准以「单个公开方法的最坏预算」算**，不是单次引擎调用。最坏的那条是 `player_move`：三次串行 `ainvoke`（`after_player → own_turn → just_moved`），中间最多 3 次 `katago.analyze`（每次 30 秒超时**且内部还会重试 1 次**）＋ 多轮 LLM ＋ 最多两轮工具轮。基准要按这个整体算，再乘 1.5~2。
3. 触发后：强制 `_set_busy(False)` + 打一行日志（便于事后归因）+ 推一条**可读提示**（不是报错刷屏）；与既有 `_set_busy` 的去重语义配合，重复解锁不得产生多余的 `busy` 事件。

> **成本修正**：加上代际守卫之后，E1 不再是「一行保险」级别的小项，而是**中等**（要碰编排的写入点）。这是为了让「防锁死」不变成「防锁死失败、改成数据错乱」——值得付。

### C2 · 局后只读回看

**为什么**：一局棋现在只在内存里，`🏁 结束` 之后你能做的只有看那段总结；「刚才那手到底亏在哪」没法回去看。

**入口**：对局结束后出现「📖 复盘」入口，进入**复盘模式**；退出时回到进去之前的样子。

**复盘模式是后端的模式，不只是前端把棋盘设成只读。** 原因：只做前端只读挡不住她出声——闲置搭话（`idle_remark`）、情绪语气词、以及玩家还能点的「💡 提示 / 📊 局面分析 / 聊天」都会让她开口，直接违反反目标。所以复盘模式要在后端**拒绝**落子 / 聊天 / 闲置，并冻结情绪心跳与语气词。

> **不改变现状的地方**：「🏁 结束」之后本来**仍然可以继续落子**（`st.finished` 被置位，但全仓没有任何地方读它——这是既有行为）。本次**不动**这个语义：复盘是一个**可进可出的独立模式**，不是「终局硬锁」。

**局面重放放在后端**：提子 / 吃子的规则在后端（`GoBoard`），前端没有这套逻辑——前端只请求「第 N 手的局面」，后端复用现有 `state` 事件推一份 `payload()`。

**回看时显示什么**：不只是棋谱。每一手旁边显示——

- 你那一手的**评定**（现有的 `E` 标签存档＝对玩家这手的分析 / 评价）；
- 她那一手的**用意**——注意：真正的「我为什么下这里」是**落子宣告**那条台词（`agent_graph._speak_own_turn` 的 `think_msg`），它**现在根本不入任何存档**；`A` 标签存的其实是**落子后感想**（`just_moved`）。两条都要，缺了「用意」这一条，复盘的价值就少一半；
- 该手若是亏损手，标出来并给出**亏损量**。

**代价（必须处理）**：

1. 现有那份带标签存档是**滚动 18 条、每条截到 80 字**（`state.py` 的 `log_memory`），拿它做整局回看会缺内容 → 为本局保留一份**不滚动、不截断**的逐手存档。
2. 落子宣告那条路径是**直发**的（不走去重闸门，见 `agent_graph.py` 文件头的硬规则）→ 新加的写入点必须是**纯追加**：不发事件、不参与去重、不改变任何既有事件与语音的配对关系。

**亏损手的数据**：现在只有 `bad_moves`＝**最近 3 条**俗手，判定是「不在我算的前 5 **或** 胜率下滑 > 10%」。

> 复盘清单**不沿用这个混合判定**——「不在前 5 但根本没掉胜率」的手其实是好手，混进「值得再看一眼」会教错人。复盘清单收的是**真正的胜率亏损**（下滑过了阈值），并按**下滑幅度**排序取前几。
>
> 因此**另开一份**「本局全部亏损手」的记录；`bad_moves` **一行不动**，右侧栏那个「俗手回档」按钮的行为保持现状（仍是最近 3 条、仍是原判定）。

**回看时她不出声**：由上面的复盘模式保证（守第四节的反目标）。

### D1 · 右栏收纳

**为什么**：右栏现在挤了 7 个开关 + 4 个按钮 + 聊天框 + 状态栏；这是「卡片挡事」那条反目标暴露出来的老问题。

**怎么做**：把**一次性设置**（`同步说话` / `整段合成` / `长句合并`）收进右栏一个「⚙ 设置」抽屉；右栏只留对局常用的（`允许虚着` / `定式导学` / `短回复` / 提示 / 分析 / 重来 / 结束 / 聊天 / 状态栏）。

**左侧栏（语音朗读）不动。** 两栏合并是候选池里的 D2，用户明确没选；本项**只收拾右栏**。（这一条是我写本文档第一版时自己写错的地方——第一版把左栏也划进了抽屉，等于偷偷做了 D2。）

**硬要求**：**收纳不能改变任何开关的语义与生效范围**。README 里那张「立即生效 / 重启后端后生效」的表是权威，挪位置之后必须仍然准确——挪完要回去核对表格与代码。

### B3 · 视角便捷

**为什么**：现在只有右键拖拽旋转 + 滚轮缩放（`Board3D.gd` 的鼠标处理），视角一旦转乱没有归位办法。

**怎么做**：加「一键回初始视角」与「看向某个角」（四个角各一个，或一个轮转按钮）。启动时那几个调试参数（`--yaw= / --pitch= / --dist= / --tilt=`）给了现成的目标值来源。

**注意**：现有键位极少被占用（键盘输入只用在聊天框那条路径上），但仍要挑不冲突、不会被误触的键位，并把操作写进 README 的「界面与操作」。

### C3 · 把「目差」翻译成人话

**为什么**：右栏那个「目差 ±x.x」对入门等于没有信息——你可能既不知道「目」是什么量级，也不知道 -3.5 算好还是算差。

**怎么做**：以**客户端为主**（不改 `info` 事件形状、不动后端），在数字旁边给一句人话解释，例如把目差映射成「差不多 / 半个角 / 一个角的实空 / 已经没法追了」这类量级描述；原始数字保留（悬停或并列显示），免得丢掉精度。

**注意**：这条要和**胜率**一起读——两者偶尔会打架（胜率 51% 但目差 -2.5 是正常的）。不要只翻译目差而让两个数字看起来矛盾。

### B2 · 最后一手标记 + 悬停坐标（**大部分已经存在**）

实际核对代码后发现，这一项要的两样**已经在代码里了**：

- 最后一手标记：`Board3D.gd` 的 `_make_stone(..., last)` 会给最后一手画一个正对玩家的圆点（黑棋青绿、白棋红）；
- 悬停显示坐标：`Board3D.gd` 的 `_tip` 会显示「`D4 · 点击落子`」。

所以本项缩成**一条残留**：

- 悬停**已有棋子**时目前**不显示任何东西**（提示只在合法空点显示）。补成「悬停任何交叉点都给坐标」，并对已有棋子额外显示**这是第几手**。

> 这条要写进 README 的界面说明（现在文档里没提悬停提示）。

## 四、反目标（沿用第一个项目的两条）

用户点名过、**即使功能跑通也算白做**的两条，对本批同样有效：

1. **她变话多** —— 定式之外同样成立：**回看模式全程不出声**（C2），不要为了「复盘讲解」再给她加戏。
2. **界面更挤** —— D1 的全部意义就是**减少**这个，不能反而更挤（抽屉本身不能再占右栏一屏）。

---

## 五、硬约束（继承项目既有，不可回退）

- **`busy` 必归位**；`agent_graph.py` 里 `_set_busy(False)` 的位置**按阶段编码、不许随意挪动**（E1 是在外面加保险，不是改里面）。
- **音画同步**：`ai_move` 带坐标，客户端等落子宣告的语音开始播放才揭示棋子（`POST /api/reveal`）。**回看模式不得干扰这条链路**。
- **一切外部能力优雅降级**，不崩、不报错刷屏。
- **后端是唯一权威**：前端只做渲染、输入、播放；C2 的局面重放必须由后端给。
- **推理段永不显示给玩家**；台词一律经 `clean_reply()` / `content_of()`。
- 改 `config.json` 字段读写的部分要守住「可执行文件同目录 → `res://config.json`」的读取顺序与 `cli_locked` 的区分。
- 前端只能在本机那台 **Godot 4.7.1** 上验证：跑完必须 `git status` 并还原任务意图之外的改动（`project.godot` 的 `config/features` 保持 `4.6`）。
- 测试：后端与 `katago_service` 都用标准库 `unittest`，**不得引入 pytest**；前端跑 headless 脚本。
